Core idea
Free memory is not one big number. It is a set of address ranges. A request succeeds only if one contiguous free range is large enough.

Allocator logic

What happens under the hood.
MODEL
1
First-fit search

Scan free blocks from the head until a block large enough for the request is found.

2
Split the free range

Return its starting offset, then shrink the free block from the front. Exact fits remove the node.

3
Insert on deallocation

Insert the released range by address so the free list stays sorted.

4
Coalesce neighbours

If one free block ends exactly where the next begins, merge them into a larger block.

This visualizer models the intended allocator behavior. It is a simulation, not a compiler or execution of the C++ source. Production code should validate frees and allocation metadata carefully.
